# 工作文档保存（save-work-doc）

将本会话中产生的文档保存到固定工作目录，按功能/需求分组管理，并在后续修改时直接定位文件、避免重复询问。

## 核心常量

- **工作文档根目录**：`/Users/pharahbai/Development/Java/Projects/work/工作文档`
- **索引文件**：`<工作文档根目录>/_index.md`（记录“功能/需求 → 文件夹/文件”的映射，供后续直接定位）

## 触发条件（何时启用本 skill）

当用户明确要求生成/编写/输出某份文档，或产出的一段内容应当被持久化为文档时启用。典型信号：

- “帮我生成一份 XX 文档”
- “把刚才的内容写成文档”
- “写一份需求文档 / 方案文档 / 接口文档 / 会议纪要”
- “这个内容保存下来，放到工作文档里”

> 仅当用户**没有**明确给出完整保存路径（此时按其路径执行，跳过询问）时才进入本流程。

---

## 流程

### Step 1 — 询问是否保存到工作目录

在把文档落盘**之前**，先向用户确认：

> 是否将这份文档保存到工作文档目录 `工作文档/` 下？

- **同意** → 继续 Step 2。
- **拒绝 / 用户只想要对话内输出** → 仅在对话中输出完整文档内容，**不写盘**，流程结束。

### Step 2 — 定位或确认分组文件夹

文档按**分类 → 功能 / 需求**分组，分类沿用索引当前结构：

- `业务项目/活动与功能`：活动、玩法、功能需求及其设计、接口、测试、配置和初始化脚本。
- `业务项目/支付与钱包`：支付渠道、支付改造/迁移、首充、钱包等支付及资金相关需求。
- `研发资产/规范与技能`：通用编码规范、开发约定、可复用技能及其参考资料。
- `研发资产/工具与配置`：通用开发工具、数据库连接配置和环境配置。
- `工作记录`：工作日志、问题排查等不归属单一项目的过程资料。

1. 先读取索引文件 `_index.md`（若存在），判断本次文档所属的功能/需求是否已有对应路径。
   - **已有** → 直接复用索引中的分类路径和文件夹，不必再询问文件夹名称。
   - **没有** → 先按资料所属的长期业务主题归入最匹配的现有分类；同一需求的说明、脚本、测试和配置资料放在同一主题目录，不按文件类型拆分。向用户确认新文件夹名称（如“订单模块”“登录需求”“XX方案”）；分类或归属不明确时一并确认。
   - 只有资料明显无法归入现有分类时才新增分类，并先与用户确认分类名称和放置位置。
2. 目录名使用清晰、稳定的业务/需求名称，优先沿用现有项目或需求名称。目标路径 = `<工作文档根目录>/<分类路径>/<文件夹名>/`。文件夹不存在则创建。

### Step 3 — 生成并保存文档

1. 生成完整文档内容。
2. 写入目标路径下，文件命名要清晰描述文档主题，例如 `<工作文档根目录>/<分类路径>/<文件夹名>/<文档主题>.md`。
3. 若同名文件已存在，**先向用户确认是否覆盖**，得到确认后再写入。

### Step 4 — 更新索引

在 `<工作文档根目录>/_index.md` 对应分类下新增或更新主题记录，保持现有分组结构，并提供主题目录及代表性文档/资料的可点击链接：

| 功能/需求 | 文件夹 | 文档与资料 |
|-----------|--------|-------------|
| 示例功能 | [示例文件夹](业务项目/活动与功能/示例文件夹/) | [示例文档](业务项目/活动与功能/示例文件夹/示例文档.md) |

- 索引链接使用相对于 `_index.md` 所在根目录的 Markdown 链接，不使用绝对路径；链接文字简短且能说明目标内容，目录链接以 `/` 结尾。
- 链接目标必须与磁盘上的实际目录或文件一致。新增、重命名、移动或删除资料时，同步修正索引链接及受影响文档中的旧路径。
- 链接路径中的空格编码为 `%20`，左右圆括号分别编码为 `%28`、`%29`；其他 URL 特殊字符也进行百分号编码。中文和普通文件名字符可直接保留。
- 若索引文件不存在，则先创建，并按上述分类/链接规则建立结构。
- 每次保存/修改后保持索引与磁盘一致；完成前检查相关链接可解析到实际目标，并检查 Markdown 链接语法。

### Step 5 — 后续文档修改（不再追问）

当用户后续在本会话（或后续会话）中要求**修改 / 更新 / 补充**某份已保存的文档时：

1. 读取 `_index.md`，按功能/需求或文档名定位到对应文件路径。
2. **直接修改该文件**，不再询问“是否保存/保存到哪/文件夹叫什么”。
3. 若索引中找不到对应记录，再向用户确认目标文件或是否新建。

## 决策分支速查

| 场景 | 行为 |
|------|------|
| 用户未给路径，要求生成文档 | 询问是否保存到 `工作文档/` → 同意则分组保存 |
| 用户给了明确路径 | 直接按路径保存，跳过询问 |
| 功能/需求已有文件夹 | 复用，不再问文件夹名 |
| 功能/需求没有文件夹 | 询问确认新文件夹名 |
| 目标文件已存在 | 先确认是否覆盖 |
| 后续修改已保存文档 | 查索引 → 直接改，不再追问 |
| 用户拒绝保存 | 仅对话内输出，不写盘 |

## 注意事项

- 根目录路径与索引路径**固定**，不要改动。
- 写入前确保父文件夹存在（不存在则用 Write 前的目录操作创建）。
- 索引文件 `_index.md` 是分类、定位和链接规范的依据，务必与磁盘实际文件保持一致；目录或文件移动后检查并更新所有受影响的链接。
- 遇到“保存到哪 / 覆盖确认 / 新文件夹名”等真正需要用户决策的点，才提问；其余情况直接执行。
